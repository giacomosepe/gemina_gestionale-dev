## Words
- **staff** = Gemina's team, mirrors the Zite table Ruoli (Amministratore → `admin`, Manager → `manager`). `former_staff` = left the team: no access, profile kept for history.
- **partner** = a segnalatore (referrer). In the Gestionale's screens Gemina's own people are called *Manager*.

## Rules
1. Every change is a file in `migrations/`, applied to dev first, tested, then to production. Never edit production by hand.
2. Only the publishable key may appear in a browser or a Zite page. Secret keys and bridge secrets live only in Supabase / Zite secret stores.
3. After every change: run the tests in `tests/` and the security advisor.

## Settings that are not SQL (set once per project)
- Auth: sign-ups disabled; site URL and redirect URLs; leaked-password protection or password sign-in off.
- Edge Function `portal-bridge` deployed (verify_jwt off: it checks its own secrets), with secrets `BRIDGE_SECRET_STAFF` and `BRIDGE_SECRET_PORTAL` (different values).
- Staff accounts are not created by hand: the bridge makes them from the Gestionale's Ruoli (see migration 20261020183659).
- Bridge action `notify` (both secrets): Zite's bell events for one current staff member. With the portal secret only the
  Portal's own events (messaggio-segnalatore, nuova-segnalazione, primo-accesso) and segnalatore links, and no actor.
  Kind `event` labels are Zite's bell text: a future unread-email job must skip them (Zite emails those itself).
- Bridge action `sync_partner` (staff secret): segnalatori created, edited, archived or deleted in the Gestionale update
  `public.partners` (deleted = archived). Edge Function settings: **production** `PARTNER_EMAILS_REAL=true`; **dev**
  `DEV_TEST_PARTNER_EMAILS` = Giacomo's test addresses (comma separated). Without them real referrer emails are replaced
  by placeholders (dev keeps no real referrer data). Archiving or an email change drops portal memberships at once;
  a deleted segnalatore is archived with its email released. Action `archive_missing_partners` (repair, run by the
  Gestionale's admin endpoint `sincronizzaSegnalatoriSupabase`) archives referrers that no longer exist in Zite.
- Referrer messages (step 6, migration 20261021133651): one conversation per referrer and subject; recipients = staff taking
  part (the colleague the referrer chose is added by bridge v6 `start_partner_conversation`); read by anyone at Gemina =
  read for the team (`staff_read_at`), referrer side `partner_read_at`; `public.partner_threads()`,
  `public.staff_colleagues()`, `public.mark_conversation_read()`. Referrers cannot create conversations from a browser.
- Message emails (Edge Function `message-emails`, verify_jwt off: it checks the internal secret): extensions `pg_net` and
  `pg_cron` (in the migration), cron job `message-emails-sweep` every 5 minutes, Vault secret `message_emails_secret`
  (generated by the migration). **Per project, once:** Vault secret `functions_url` =
  `https://<ref>.supabase.co/functions/v1` (`select vault.create_secret('<url>', 'functions_url');`); until it exists no
  email is requested. Edge Function secret `RESEND_API_KEY` (Giacomo, dashboard).
- History import of Zite messages: in one transaction with `select set_config('gemina.import', 'on', true)` and no user;
  never set it session-wide.
- Referrer documents (step 7, migration 20261021145534): files and links between Gemina and the segnalatori in
  `public.documents` and the private bucket `documents`. The browser creates the row (the server makes the path
  `partner/<partner>/<document>/<name>` and checks the scope), uploads with its own login, then calls
  `public.confirm_document_upload()`. Also `public.partner_documents()`, `public.remove_document()` (hides, the file stays),
  `public.notify_document()` ("Notifica segnalatore": bell + email, message-emails mode `document`),
  `public.mark_documents_read()`. A segnalatore's file outside a message → team bell (kind `document`) and the team email
  after 15 minutes, like messages.
- Automatic messages (migration 20261021155543): `messages.automatic` = a message signed Gemina Advisory with no sender, written
  only by the bridge (v7 action `post_automatic_message`, staff secret) for the Gestionale's own notices; only the segnalatore
  gets a bell, no Supabase email (Zite sends its own). "Notifica segnalatore" ignores a second press within a minute.
- Team documents and reminders (migrations 20261021221703 + 20261021221829): `documents.kind = 'team'` = Gemina's own files on a
  pratica (azione attachments; path `team/<pratica>/<doc>/<name>`, staff only, never shared, `zite_attivita_id` optional), listed in
  the pratica's «Documenti dal server». `public.reminders` (one per pratica and date key; staff write from the browser; recipients =
  Zite user ids) + `public.reminder_sends`; pg_cron job `pratica-reminders` every hour at :05 runs `private.send_due_reminders()`,
  which acts at 8 in Rome: bell (kind `event`, event `promemoria`, link `pratica:<id>`) and message-emails mode `reminders`.
- Azienda as home of team documents (migration 20261022145359, test 009): a `team` document always has `zite_azienda_id`
  (path `team/<azienda>/<doc>/<name>`), may be about a trattativa and/or a pratica, and has `lifespan` `company` (default:
  serves every project of the azienda, e.g. bilanci with `category = 'Bilancio <anno>'`) or `project` (needs a trattativa or
  pratica). Views read across (a pratica shows the azienda's documents and its own); nothing is copied. Bucket limit 50 MB.
  A reminder is about exactly one pratica or trattativa (`zite_trattativa_id`); the bell links `trattativa:<id>` for the latter.
- Security advisor, expected warnings: leaked-password protection; `authenticated_security_definer_function_executable` for
  `mark_conversation_read`, `partner_threads`, `staff_colleagues`, `confirm_document_upload`, `remove_document`,
  `notify_document`, `mark_documents_read`, `partner_documents` (meant to be called by signed-in users; each checks the
  caller inside).
- Later: token hook, MFA.
